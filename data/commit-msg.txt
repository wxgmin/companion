Add hearing, a 3D avatar, and a one-click desktop launch

Getting her on screen meant answering two questions the docs do not cover: what
AIRI persists, and which provider can actually speak.

AIRI's settings are not in a config file. They live in Chromium Local Storage
(LevelDB) alongside the profile, so there is no file to edit and no CLI. The
neighbouring JSON files hold window geometry, language and MCP servers only.
tools/airi-config writes the store directly, which is also the only way to make
setup reproducible for someone cloning this repo. It backs the store up first,
refuses to write while AIRI holds the lock, and says so plainly instead of
reporting a corrupt profile.

The provider choice is a trap worth documenting. openai-compatible sounds like
the right provider for a local OpenAI-shaped server, but it declares
tasks:['chat'] and can never be selected for voice. The one that works is
openai-audio, which builds both a speech and a transcription client from a
single baseUrl - which is why the voice server now serves both routes rather
than TTS alone.

For the avatar, AIRI already bundles two VRM models and ships a real lip-sync
implementation (lip-sync.ts plus a 37 KB profile). preset-vrm-1 is
AvatarSample_A, a 3D model with the blend shapes lip-sync drives, licensed with
redistribution=allow. The previous preset-live2d-1 was the 2D default.

  speech        chatterbox via :8092/v1
  hearing       whisper via :8092/v1
  consciousness qwen38-local:latest via ollama
  stage         preset-vrm-1 (3D + lip-sync)

Three scripts tie it together:

  start_companion.ps1   Ollama, then voice, then AIRI - in that order, because
                        AIRI calling an unloaded model looks like a hang.
                        Idempotent, so a second run does not duplicate anything.
  install_shortcut.ps1  puts "Her" on the Desktop, minimised rather than hidden
                        so a failure is visible instead of silent.
  check_voice_api.py    round-trips a sentence through speech and back, and
                        compares the text. Currently 100% word overlap.

faster-whisper was added to the voice venv to serve transcription. It pulls only
av, ctranslate2, flatbuffers and onnxruntime - no torch - so the CUDA wheel is
untouched (verified before and after: 2.14.0+cu126).
